# 마토메 보드

일본 게임·애니·버튜버·만화 공연과 이벤트 소식을 모아 보는 공개 페이지입니다.
GitHub Pages로 공개되고, GitHub Actions가 하루 4번(일본 시간 6·12·18·24시) 소식을 자동으로 갱신합니다.

## 처음 한 번만 하는 설정

1. **저장소 만들기**: GitHub에서 새 저장소를 **Public**으로 만들고, 이 폴더의 파일을 전부 올립니다.
   (웹에서는 *Add file → Upload files*에 폴더째 끌어다 놓으면 됩니다. `.github` 폴더도 꼭 함께 올려 주세요.)
2. **페이지 공개**: *Settings → Pages*에서 *Source*를 `Deploy from a branch`, 브랜치 `main`, 폴더 `/ (root)`로 저장합니다.
   1~2분 뒤 `https://<아이디>.github.io/<저장소이름>/` 주소가 생깁니다. 이 주소를 친구에게 보내면 됩니다.
3. **자동 업데이트 권한**: *Settings → Actions → General → Workflow permissions*에서 `Read and write permissions`를 고릅니다.
4. **(선택) 키 등록**: *Settings → Secrets and variables → Actions → New repository secret*
   - `ANNICT_TOKEN`: annict.com 설정 → 애플리케이션에서 발급. 없어도 방영 목록은 AniList(키 불필요)에서 받아오고, 있으면 Annict 정보를 덧붙입니다.
   - `HOLODEX_API_KEY`: holodex.net 계정 설정에서 발급. 버튜버 방송 예정에 사용. (키가 없어도 ホロライブ·にじさんじ·ぶいすぽっ 공식 뉴스와 PANORA 의 버튜버 이벤트·굿즈 소식은 들어옵니다.)
   키가 없어도 뉴스 수집과 PV 썸네일은 동작합니다.
5. **첫 실행**: *Actions → 소식 자동 업데이트 → Run workflow*. 이후로는 알아서 돌아갑니다.

## 운영하는 법

| 하고 싶은 것 | 고칠 파일 |
|---|---|
| 소식을 직접 추가 | `data/manual.json` |
| 공개 보드에서 소식 빼기 | `data/blocklist.json` (`urls`, `titles`에 추가) |
| 만갤 탭에 작품 더하기·빼기 | `data/comics_follow.json`의 `follow`에 `{"title": 작품 이름, "posts": [그 작품 아무 화의 디시 주소]}`를 더하거나 지움 |
| 주간 요약 쓰기 | `data/weekly.json` (아래 "주간 요약 탭" 참고. 클로드 세션에 "이번 주 요약 만들어 줘"라고 하면 유행 작품을 골라 검색해 써 준다) |
| 수집할 사이트 바꾸기 | `collector.py`의 `SOURCES` (고친 뒤 *Actions → 소스 점검 → Run workflow*로 OK/FAIL 확인) |
| 방송 요일·시각 고치기 | `data/anime.json` (목록 자체는 AniList에서 매번 새로 받으므로 방송국 `st` 같은 값만 손보면 됨) |

GitHub 웹에서 파일을 열고 연필 아이콘으로 고친 뒤 *Commit changes*를 누르면 몇 분 안에 반영됩니다.

`data/manual.json`에 넣는 소식 형식:

```json
[
  {
    "title": "행사 이름",
    "category": "live",
    "source": "출처",
    "works": ["작품명"],
    "eventDate": "2026-12-19T18:00",
    "endDate": "",
    "ticketOpen": "",
    "deadline": "",
    "venue": "장소",
    "ticketUrl": "https://eplus.jp/...",
    "url": "https://공식 공지 주소",
    "summary": "한 줄 요약"
  }
]
```

`category`는 `live`(공연) · `event`(이벤트) · `official`(공식 행사) · `doujin`(동인·온리전) · `collab`(콜라보) · `popup`(팝업) · `exhibit`(전시·원화전) · `manga`(만화 소식) · `goods` · `stream` · `campaign` · `other` 중 하나입니다. 날짜는 일본 시간입니다.

## 보는 사람 입장

- 기본 표시는 일본어 원문입니다. 맨 위의 한국어를 누르면 수집할 때 Google 번역으로 만든 기계 번역으로 제목과 요약만 바뀝니다(어색한 번역이 많아 참고용). 장소·작품명은 늘 원문입니다.
- 로그인이나 설정 없이 누구나 봅니다. 피드에서 버튜버만 고르거나 날짜순으로 볼 수 있고, 캘린더에서 날을 누르면 그날 일정이 나옵니다.
- "방영중"의 ‘보는 중’ 목록만 각자 브라우저에 저장되고, 그 밖의 개인 설정은 없습니다. 특정 소식을 빼고 싶으면 운영자가 `data/blocklist.json`에 넣습니다.
- 소식은 공식 사이트와 뉴스 RSS에서 자동으로 모으므로 날짜·예약 정보는 원문에서 꼭 확인하도록 안내돼 있습니다.

## 게시판 설정 (한 번만, 5분)

"사이트 개요" 탭의 게시판은 누구나 익명으로 쓰고, 올린 글은 고치거나 지울 수 없습니다. 정적 페이지라 글을 담아 둘 곳이 필요한데, Google 스프레드시트에 붙인 작은 스크립트(Apps Script 웹 앱)를 씁니다. 설정 전에는 "준비 중"으로 보입니다.

1. **스프레드시트 만들기**: [sheets.new](https://sheets.new) 에서 새 스프레드시트를 만듭니다(이름은 아무거나).
2. **스크립트 붙여 넣기**: 메뉴 *확장 프로그램 → Apps Script* → 열린 편집기의 내용을 지우고 이 저장소의 [`bbs/Code.gs`](bbs/Code.gs) 내용을 붙여 넣고 저장(디스크 아이콘).
3. **웹 앱으로 배포**: 오른쪽 위 *배포 → 새 배포* → 톱니에서 유형 **웹 앱** → *실행 사용자* **나** · *액세스 권한* **모든 사용자** → 배포. 처음에는 권한 승인 창이 뜹니다(내 계정 선택 → 고급 → 이동 → 허용).
4. **주소 복사**: 나온 *웹 앱 URL*(`https://script.google.com/macros/s/…/exec`)을 복사합니다.
5. **index.html 채우기**: 파일 위쪽의 `const BBS = { api: "" }` 에 그 주소를 넣고 커밋합니다.

글은 스프레드시트의 `posts` 시트에 시각·이름·내용으로 쌓입니다. 지워야 할 글은 그 행을 삭제하면 됩니다. 스크립트를 고친 뒤에는 *배포 → 배포 관리 → 수정 → 새 버전* 으로 다시 배포해야 반영됩니다. 같은 브라우저에서는 30초에 한 번만 올릴 수 있고, 글은 500자까지입니다.

## 장소·도쿄 지도

공연·행사에 장소가 있으면 카드에 장소 줄이 붙고, 누르면 구글 지도가 열립니다. 피드 맨 위의 **도쿄 지도**를 펼치면 앞으로 열릴 행사장이 점으로 찍혀 있고(23구 / 수도권: 幕張·舞浜·横浜·川崎·さいたま까지), ◆는 행사가 자주 열리는 동네입니다. 점을 누르면 그곳 행사 목록이, 행사를 누르면 해당 카드로 이동합니다. 좌표는 アニメハック 이벤트 캘린더에 들어 있는 값을 그대로 쓰고, 지도는 외부 지도 서비스 없이 페이지 안에서 그립니다.

## 만갤 탭 (연재 만화)

디시인사이드 만화 갤러리에서 **지정한 연재작만** 1화부터 순서대로 보여 줍니다. 작품 목록은 `data/comics_follow.json`이고, 작품마다 제목(`title`, 디시 글 제목에서 `번역)` 같은 말머리와 회차를 뗀 이름)과 회차 목록을 읽을 글 주소(`posts`, [시리즈] 상자가 붙은 아무 화나 "링크 모음" 글)를 적습니다. 새 화는 개념글과 제목 검색으로 자동으로 붙습니다. 닌자 슬레이어처럼 운영자가 정리 글(목차)을 따로 두는 작품은 `index`에 그 정리 글 주소를, `gallery`에 번역이 올라오는 갤러리 아이디를 적으면 정리 글의 부·권·에피소드 순서 그대로 목차를 만들고, 갤러리에 새로 올라온 번역 글을 뒤에 더합니다(원본만 올리는 닉은 `raw_nicks`, 제목 줄임말은 `aliases`에). 그림은 저장하지 않고 원문 글로 연결하며, 각자 마지막으로 연 화를 브라우저에 기억해 "이어 보기"를 띄웁니다. 연재작 제목을 달고 엉뚱한 그림(니세코이 짤)을 올린 낚시글은 그림으로 알아보고 뺍니다. 새 낚시 그림이 생기면 그 해시를 `data/blocklist.json`의 `comic_images`에 더합니다.

## 주간 요약 탭

캘린더 옆 "주간 요약"은 사람이 쓰는 글입니다. 보드에 가장 많이 오른 작품(`data/meta.json`의 유행 순위) 중심으로 소식 몇 개를 골라 번호를 매기고, **설명은 보드의 기사 본문이 아니라 따로 검색한 공식 발표·언론 기사**로 정리해 그 글을 '출처'로 답니다. 내용은 `data/weekly.json` 하나이고 매주 덮어씁니다.

```json
{"week":"2026-10-26", "range":"10/26(일) ~ 11/1(일)", "title":"이번 주 요약 · 10월 마지막 주", "updated":"2026-10-24",
 "picks":[{"title":"소식 제목", "works":["작품명"], "category":"collab", "tag":"유행 1위",
           "when":"언제(자유 서식)", "where":"어디서", "desc":"검색해서 정리한 배경 설명(몇 문장)",
           "links":[{"label":"출처 이름", "url":"https://..."}], "items":["보드에 있는 관련 소식의 url"]}]}
```

`items`에 적은 주소가 보드 소식과 같으면 제목·날짜를 보드에서 가져와 보여 주고, 누르면 피드의 그 카드로 이동합니다(끝난 소식은 원문을 엽니다). `category`는 소식의 분류와 같은 값(`collab`·`live`·`exhibit` …), `tag`는 "유행 1위"·"마감 임박" 같은 짧은 배지입니다. 파일이 없거나 비어 있으면 탭에 "아직 없어요"만 나옵니다.

## 弾幕 탭 (미니 게임)

「まとめ結界 / MAID BUSTER LILLY」는 탭 하나짜리 세로 탄막 게임입니다. 화면을 드래그해 움직이고(PC는 방향키), 공격은 자동, 피탄 판정은 가운데 점 하나. 5스테이지(ミニオン襲来 → 蒼の艦隊 → オーバーロード再臨 → 要塞宙域 → 最終決戦)로 잡몹 → 중보스 → 보스(必殺技 3개) 순이고, 必殺技를 피탄·結界 없이 깨면 보너스. 그림은 운영자가 만든 스프라이트 시트(`assets/game/src/`)에서 `python3 assets/game/extract.py`로 잘라낸 `assets/game/*.png`이고, 우주 배경만 `python3 assets/game/paint.py`가 그립니다(둘 다 Pillow·numpy). 다른 조각을 쓰고 싶으면 `extract.py scan 폴더`로 번호 시트를 뽑아 `PICKS`의 번호를 바꾸면 됩니다. BGM(16비트풍, 스테이지·보스·타이틀 3곡)은 브라우저가 소리를 내므로 ♪ BGM 버튼으로 끌 수 있습니다. 최고 점수는 각자 브라우저에만 남습니다.

## Holo Mobile 탭

운영자가 만든 홀로라이브 캐릭터 스이카 & 2048 모바일판(`games/holo2048.html`)을 탭 안에 그대로 띄웁니다. 파일을 통째로 바꾸면 반영되고, 기록은 각자 브라우저에만 남습니다.

## 방문자 수 보기

[teraee.goatcounter.com](https://teraee.goatcounter.com) 에 로그인하면 일별 방문자·조회수·유입 경로가 보입니다. GitHub 저장소의 *Insights → Traffic* 은 github.com 저장소 페이지 방문만 세므로 사이트 방문과는 다릅니다.

## 참고

- 썸네일은 작품 공식 사이트의 대표 이미지(og:image)를 작게 줄여 `data/thumbs/`에 저장해 씁니다. 공식 사이트가 없으면 공식 PV 대표 이미지를 씁니다.
- 기사 본문은 저장하지 않고 제목·요약·원문 링크만 담습니다.
- 링크를 카카오톡·X 등에 붙이면 `assets/og.png`가 미리보기로 뜹니다. 바꾸려면 같은 크기(1200×630)의 PNG로 교체하면 됩니다. 공유 앱이 예전 이미지를 기억하고 있으면 주소 끝에 `?v=2` 처럼 아무 글자를 붙여 다시 공유하면 새로 읽습니다.
