# 마토메 보드

일본 게임·애니·버튜버·만화 공연과 이벤트 소식을 모아 보는 공개 페이지입니다.
GitHub Pages로 공개되고, GitHub Actions가 하루 4번(일본 시간 6·12·18·24시) 소식을 자동으로 갱신합니다.

## 처음 한 번만 하는 설정

1. **저장소 만들기**: GitHub에서 새 저장소를 **Public**으로 만들고, 이 폴더의 파일을 전부 올립니다.
   (웹에서는 *Add file → Upload files*에 폴더째 끌어다 놓으면 됩니다. `.github` 폴더도 꼭 함께 올려 주세요.)
2. **페이지 공개**: *Settings → Pages*에서 *Source*를 `Deploy from a branch`, 브랜치 `main`, 폴더 `/ (root)`로 저장합니다.
   1~2분 뒤 `https://<아이디>.github.io/<저장소이름>/` 주소가 생깁니다. 이 주소를 친구에게 보내면 됩니다.
3. **자동 업데이트 권한**: *Settings → Actions → General → Workflow permissions*에서 `Read and write permissions`를 고릅니다.
4. **(선택) 키 등록**: *Settings → Secrets and variables → Actions → New repository secret*
   - `ANNICT_TOKEN`: annict.com 설정 → 애플리케이션에서 발급. 없어도 방영 목록은 AniList(키 불필요)에서 받아오고, 있으면 Annict 정보를 덧붙입니다.
   - `HOLODEX_API_KEY`: holodex.net 계정 설정에서 발급. 버튜버 방송 예정에 사용. (키가 없어도 ホロライブ·にじさんじ·ぶいすぽっ 공식 뉴스와 PANORA 의 버튜버 이벤트·굿즈 소식은 들어옵니다.)
   키가 없어도 뉴스 수집과 PV 썸네일은 동작합니다.
5. **첫 실행**: *Actions → 소식 자동 업데이트 → Run workflow*. 이후로는 알아서 돌아갑니다.

## 운영하는 법

| 하고 싶은 것 | 고칠 파일 |
|---|---|
| 소식을 직접 추가 | `data/manual.json` |
| 공개 보드에서 소식 빼기 | `data/blocklist.json` (`urls`, `titles`에 추가) |
| 같은 작품이 두 이름으로 갈라질 때 · 작품 허브의 한국어 이름 | `data/works.json` (`alias`에 "다른 이름": "대표 이름", `ko`에 "대표 이름": "한국어 이름") |
| 만갤 탭에 작품 더하기·빼기 | `data/comics_follow.json`의 `follow`에 `{"title": 작품 이름, "posts": [그 작품 아무 화의 디시 주소]}`를 더하거나 지움 |
| 주간 요약 쓰기 | `data/weekly.json` (아래 "주간 요약 탭" 참고. 클로드 세션에 "이번 주 요약 만들어 줘"라고 하면 유행 작품을 골라 검색해 써 준다) |
| 수집할 사이트 바꾸기 | `collector.py`의 `SOURCES` (고친 뒤 *Actions → 소스 점검 → Run workflow*로 OK/FAIL 확인) |
| 방송 요일·시각 고치기 | `data/anime.json` (목록 자체는 AniList에서 매번 새로 받으므로 방송국 `st` 같은 값만 손보면 됨) |

GitHub 웹에서 파일을 열고 연필 아이콘으로 고친 뒤 *Commit changes*를 누르면 몇 분 안에 반영됩니다.

`data/manual.json`에 넣는 소식 형식:

```json
[
  {
    "title": "행사 이름",
    "category": "live",
    "source": "출처",
    "works": ["작품명"],
    "eventDate": "2026-12-19T18:00",
    "endDate": "",
    "ticketOpen": "",
    "deadline": "",
    "venue": "장소",
    "ticketUrl": "https://eplus.jp/...",
    "url": "https://공식 공지 주소",
    "summary": "한 줄 요약"
  }
]
```

`category`는 `live`(공연) · `event`(이벤트) · `official`(공식 행사) · `doujin`(동인·온리전) · `collab`(콜라보) · `popup`(팝업) · `exhibit`(전시·원화전) · `manga`(만화 소식) · `goods` · `stream` · `campaign` · `other` 중 하나입니다. 날짜는 일본 시간입니다.

## 보는 사람 입장

- 기본 표시는 일본어 원문입니다. 맨 위의 한국어를 누르면 수집할 때 Google 번역으로 만든 기계 번역으로 제목과 요약만 바뀝니다(어색한 번역이 많아 참고용). 장소·작품명은 늘 원문입니다. 번역문 속 작품 이름은 `data/works.json`의 `ko` 한국어 이름으로 통일됩니다(예: 薬屋のひとりごと → 약사의 혼잣말). 한국어 이름을 더하거나 고치면 다음 갱신부터 그 작품이 든 소식을 다시 번역합니다.
- 로그인이나 설정 없이 누구나 봅니다. 피드에서 버튜버만 고르거나 날짜순으로 볼 수 있고, 캘린더에서 날을 누르면 그날 일정이 나옵니다.
- "방영중"의 ‘보는 중’ 목록만 각자 브라우저에 저장되고, 그 밖의 개인 설정은 없습니다. 특정 소식을 빼고 싶으면 운영자가 `data/blocklist.json`에 넣습니다.
- 소식은 공식 사이트와 뉴스 RSS에서 자동으로 모으므로 날짜·예약 정보는 원문에서 꼭 확인하도록 안내돼 있습니다.

## 게시판 설정 (한 번만, 5분)

"사이트 개요" 탭의 게시판은 누구나 익명으로 쓰고, 올린 글은 고치거나 지울 수 없습니다. 정적 페이지라 글을 담아 둘 곳이 필요한데, Google 스프레드시트에 붙인 작은 스크립트(Apps Script 웹 앱)를 씁니다. 설정 전에는 "준비 중"으로 보입니다.

1. **스프레드시트 만들기**: [sheets.new](https://sheets.new) 에서 새 스프레드시트를 만듭니다(이름은 아무거나).
2. **스크립트 붙여 넣기**: 메뉴 *확장 프로그램 → Apps Script* → 열린 편집기의 내용을 지우고 이 저장소의 [`bbs/Loader.gs`](bbs/Loader.gs)(20줄짜리 로더) 내용을 붙여 넣고 저장(디스크 아이콘). 로더는 실행될 때마다 GitHub의 [`bbs/Code.gs`](bbs/Code.gs)를 읽어(10분 캐시) 실행하므로, **게시판·스코어 보드 코드가 바뀌어도 다시 붙여 넣거나 다시 배포할 필요가 없습니다.** 폰에서는 Chrome 메뉴의 *데스크톱 사이트*를 켜고 script.google.com 을 열면 편집기를 쓸 수 있습니다. 함수 `setup`을 한 번 실행(▷)해 권한을 승인해 두면 좋습니다.
3. **웹 앱으로 배포**: 오른쪽 위 *배포 → 새 배포* → 톱니에서 유형 **웹 앱** → *실행 사용자* **나** · *액세스 권한* **모든 사용자** → 배포. 처음에는 권한 승인 창이 뜹니다(내 계정 선택 → 고급 → 이동 → 허용).
4. **주소 복사**: 나온 *웹 앱 URL*(`https://script.google.com/macros/s/…/exec`)을 복사합니다.
5. **index.html 채우기**: 파일 위쪽의 `const BBS = { api: "" }` 에 그 주소를 넣고 커밋합니다.

글은 스프레드시트의 `posts` 시트에 시각·이름·내용으로 쌓입니다. 지워야 할 글은 그 행을 삭제하면 됩니다. 로더 대신 `Code.gs`를 직접 붙여 넣은 경우에는 코드를 바꿀 때마다 다시 붙여 넣고 *배포 → 배포 관리 → 수정 → 새 버전* 으로 다시 배포해야 반영됩니다(로더는 저장소 `main`의 코드를 그대로 실행하므로, 저장소에 푸시할 수 있는 사람은 그 코드를 운영자 구글 계정 권한으로 돌릴 수 있다는 점도 알아 두세요). 같은 브라우저에서는 30초에 한 번만 올릴 수 있고, 글은 500자까지입니다.

**글이 안 읽힐 때**: 웹 앱 주소를 브라우저로 직접 열어 보세요. `{"posts":[…]}`가 나오면 정상, `{"error":"…"}`가 나오면 그 내용이 원인이고(페이지에도 같은 문구가 뜹니다), 구글 로그인·권한 화면이 나오면 *액세스 권한*이 **모든 사용자**가 아닌 것입니다. 스크립트를 스프레드시트의 *확장 프로그램 → Apps Script*가 아니라 script.google.com 에서 따로 만들었다면, `Code.gs` 맨 위 `SHEET_ID`에 쓸 스프레드시트의 ID(주소의 `/d/`와 `/edit` 사이)를 적거나, 비워 두면 처음 실행할 때 '마토메 보드 게시판' 스프레드시트를 새로 만들어 씁니다. 편집기에서 함수 `setup`을 한 번 실행(▷)하면 권한 승인과 함께 실행 로그에 쓰는 스프레드시트 주소가 나옵니다.

**예전 게시판 글 옮기기**: 웹 앱을 새로 배포해 스프레드시트가 바뀌었으면, 새 웹 앱이 처음 열릴 때 예전 웹 앱(`Code.gs`의 `OLD_API`)에서 글(최신 500건)과 스코어 보드 기록을 한 번 가져와 합칩니다(겹치는 글은 빼고 시각 순). 예전 웹 앱 배포는 지우지 말고 두세요.

**Holo Mobile 스코어 보드**도 같은 웹 앱을 씁니다. 수박 게임·2048 퍼즐이 끝나 결과 창이 뜨면 게임 아래에 등록 칸이 열리고, 기록은 `scores_suika`·`scores_2048` 시트에 따로 쌓입니다(로더를 쓰면 따로 할 일 없음).

**弾幕 스코어 보드**도 같은 웹 앱을 씁니다. 게임이 끝나면(게임 오버·올 클리어) 게임 아래 스코어 보드에 이름(12자)을 적어 기록을 남길 수 있고, 점수 높은 순 TOP 30이 보입니다. 기록은 같은 스프레드시트의 `scores` 시트(시각·이름·점수·스테이지·스킨·클리어)에 쌓이며 처음 등록할 때 시트가 생깁니다. 이상한 기록은 그 행을 지우면 됩니다(점수는 브라우저가 보내는 값이라 조작을 막을 수는 없습니다). 웹 앱이 스코어 보드가 없는 예전 코드면 스코어 보드가 "준비 중"으로 보입니다(로더를 쓰면 자동으로 최신).

## 장소·도쿄 지도

공연·행사에 장소가 있으면 카드에 장소 줄이 붙고, 누르면 구글 지도가 열립니다. 피드 맨 위의 **도쿄 지도**를 펼치면 앞으로 열릴 행사장이 점으로 찍혀 있고(23구 / 수도권: 幕張·舞浜·横浜·川崎·さいたま까지), ◆는 행사가 자주 열리는 동네입니다. 점을 누르면 그곳 행사 목록이, 행사를 누르면 해당 카드로 이동합니다. 좌표는 アニメハック 이벤트 캘린더에 들어 있는 값을 그대로 쓰고, 지도는 외부 지도 서비스 없이 페이지 안에서 그립니다.

## 작품 탭 (작품 허브)

유행 순위에 오른 작품과 지금 소식이 있는 작품을 카드로 모아 보여 주고, 누르면 그 작품의 **지금 소식·방영 정보·만갤 연재·최근 14일 유행 추이·주간 요약 설명**을 한 화면에 모읍니다. 피드 카드의 작품 이름, 주간 요약의 작품 이름, 방영중의 "관련 소식 n건"을 눌러도 같은 화면으로 옵니다. 주소가 `…/#work=ちいかわ`처럼 바뀌니 "링크 공유"로 친구에게 그대로 보낼 수 있습니다. 검색은 일본어 이름과 `ko`에 적은 한국어 이름 둘 다 됩니다. 카드에는 방영 썸네일이나 관련 기사의 대표 이미지가 붙고(없으면 색 타일), 맨 위 **급상승** 줄은 최근 3일 기사가 그 전보다 크게 늘어난 작품입니다(피드 카드에도 "급상승" 배지).

## 검색 · 내 작품 · 새 소식

피드 맨 위 검색창에서 제목·장소·작품 이름(한국어 이름도)으로 지금 소식을 찾습니다. 작품 화면의 **☆ 내 작품에 추가**를 누르면 그 작품이 작품 목록 맨 앞에 오고, 피드의 **★ 내 작품** 칩으로 그 작품 소식만 모아 봅니다. 30분 넘게 있다가 다시 들어오면 지난 방문 뒤에 들어온 소식에 NEW 배지가 붙고, 피드 위에 "새 소식 n건 · 내 작품 n건"이 나옵니다. 내 작품과 방문 기록은 각자 브라우저에만 남습니다.

여러 매체가 같은 행사를 따로 보도하면(행사일이 같고 제목이 비슷하면) 카드 하나로 묶고 "외 n곳"과 다른 기사 링크를 답니다. 작품 화면에는 그 작품 소식에 같이 나온 작품(콜라보 상대 등)도 보여 줍니다.

## 이번 주말

캘린더의 **이번 주말** 버튼은 이번 토·일에 열려 있는 행사를 지역(도쿄는 구, 그 밖은 도·현)별로 묶어 보여 주고, 도쿄 지도의 **이번 주말** 칩은 그 행사장만 점으로 찍습니다.

## RSS · 출처 상태

`data/feed.xml`은 새 소식 60건과 이번 주간 요약을 담은 RSS입니다(사이트 개요에 링크). RSS 앱이나 디스코드 RSS 봇에 넣으면 갱신마다 받아 볼 수 있습니다. 사이트 개요의 **출처 상태** 표는 매 갱신에서 출처별로 정상/실패와 가져온 수를 보여 줍니다. 같은 출처가 3번 연속 실패하거나 이틀 내내 피드가 비면, 봇이 이 저장소에 **`[자동] 소식 출처 수집 이상` 이슈**를 열어 GitHub 알림(메일)으로 알려 줍니다. 그 사이트 주소나 구조가 바뀐 것이니 `collector.py`의 `SOURCES`를 고치고 Actions의 "소스 점검"으로 확인하면 되고, 회복되면 이슈는 자동으로 닫힙니다. 한 번 실행에서 출처가 **절반 넘게** 실패하면 출처가 아니라 수집기 자체(코드·네트워크)가 고장 난 것으로 보고, 그 실행은 데이터를 커밋하지 않고(보드는 이전 소식 그대로) 바로 **`[자동] 수집기 고장 — 데이터 갱신 멈춤` 이슈**를 엽니다. 다음 실행이 정상이면 닫힙니다.

PR을 올리거나 main에 코드를 푸시하면 Actions의 **코드 점검**이 수집기 문법·정의 안 된 이름·가짜 피드로 한 바퀴 돌리기(`tests/smoke.py`)·페이지 스크립트 문법(`tests/jscheck.py`)·실제 브라우저로 폰 크기에서 탭마다 오류와 화면 넘침이 없는지(`tests/pagecheck.js`)를 확인합니다. 빨간 X가 뜨면 머지하지 마세요.

## 홈 화면 앱

## X 화제 탭

X(트위터)에서 지금 화제인 이야기를 **Togetter**(X 게시물을 사람이 주제별로 묶은 정리 사이트)의 인기 목록과 새 정리에서 하루 4번 모아 일주일치 보여 줍니다. X는 2026년부터 무료 API가 없어서 직접 읽지 않고, Togetter 정리의 제목·링크·대표 그림만 가져옵니다(누르면 Togetter가 열림). "🔥 인기"는 Togetter 인기 상위 10개에 오른 것, "애니·게임"은 보드 작품 이름이나 애니·만화·게임·성우·버튜버 단어가 든 것, "★ 내 작품"은 내 작품 이름이 든 것입니다. 작품 화면에도 그 작품의 "X 반응"이 붙고, 작품 목록에는 "X 언급 n"과 맨 위 **X에서 화제**(최근 일주일 Togetter 정리에 많이 나온 작품) 줄이 보입니다. 뉴스 기반 유행 순위와는 따로 셉니다. X 이용자 반응을 모은 것이라 사실과 다를 수 있습니다.

## 달력 구독

사이트 개요의 **달력 구독**에서 "전부 / 행사만 / 예매·마감만" 중 하나를 골라 구글 캘린더나 아이폰 캘린더에 구독하면, 하루 4번 갱신될 때마다 새 일정이 달력에 저절로 들어오고 바뀐 날짜도 따라갑니다(달력 앱이 몇 시간마다 다시 읽음). 예매·마감 달력은 아이폰에서 30분 전 알림이 뜹니다(구글은 구독 달력 알림을 지원하지 않음).

## 장소 사전

콜라보·팝업 기사는 장소 칸이 비어 있는 경우가 많아, `data/venues.json`의 장소 사전으로 제목·요약에서 장소를 찾아 지도·이번 주말·달력에 넣습니다(카드에 "기사 기준" 표시). 자주 나오는데 사전에 없는 장소가 있으면 `venues`에 이름·좌표를 더하고, 좌표가 틀렸으면 고치면 다음 갱신부터 반영됩니다. 여러 곳에서 열리는 행사("4会場", "順次", "全国")는 한 점으로 찍지 않습니다.

## 소식 공유 · 지난 소식 검색

카드의 **공유**를 누르면 그 소식으로 바로 가는 링크(`…/#item=…`)를 보냅니다. 받은 사람은 피드 맨 위에 그 소식이 강조된 채로 보입니다(끝난 소식이어도 보임). 검색할 때 **지난 소식 포함**을 켜면 끝난 소식도 찾습니다.

## 달력에 추가

날짜가 있는 소식 카드의 **📅 달력에 추가**를 누르면 `.ics` 파일을 받습니다. 열면 휴대폰 달력·구글 캘린더·아웃룩에 행사일(기간이면 시작~끝), 판매·추첨 시작, 마감이 일정으로 들어가고, 판매 시작·마감은 30분 전에 알림이 뜹니다. 작품 허브의 **이 작품 일정 전부 달력에**는 그 작품의 일정을 한 파일로 받습니다.

작품 이름은 전각/반각(`ゴジラ－0.0`/`ゴジラ-0.0`), `！`/`!`, 앞에 붙은 『 차이를 자동으로 같은 작품으로 봅니다. 「薬屋のひとりごと 亡妃の秘宝」처럼 작품 이름 뒤에 부제가 붙은 것도 그 작품으로 묶습니다. 그래도 갈라지는 다른 이름(약칭·영문 표기)은 `data/works.json`의 `alias`에 적고, 유행 순위에 작품이 아닌 이름(가게·행사 등)이 오르면 `skip`에 적습니다. 다음 갱신부터 수집기와 페이지 양쪽에 반영됩니다.

## 만갤 탭 (연재 만화)

디시인사이드 만화 갤러리에서 **지정한 연재작만** 1화부터 순서대로 보여 줍니다. 작품 목록은 `data/comics_follow.json`이고, 작품마다 제목(`title`, 디시 글 제목에서 `번역)` 같은 말머리와 회차를 뗀 이름)과 회차 목록을 읽을 글 주소(`posts`, [시리즈] 상자가 붙은 아무 화나 "링크 모음" 글)를 적습니다. 새 화는 개념글과 제목 검색으로 자동으로 붙습니다. 닌자 슬레이어처럼 운영자가 정리 글(목차)을 따로 두는 작품은 `index`에 그 정리 글 주소를, `gallery`에 번역이 올라오는 갤러리 아이디를 적으면 정리 글의 부·권·에피소드 순서 그대로 목차를 만들고, 갤러리에 새로 올라온 번역 글을 뒤에 더합니다(원본만 올리는 닉은 `raw_nicks`, 제목 줄임말은 `aliases`에). 그림은 저장하지 않고 원문 글로 연결하며, 각자 마지막으로 연 화를 브라우저에 기억해 "이어 보기"를 띄웁니다. 연재작 제목을 달고 엉뚱한 그림(니세코이 짤)을 올린 낚시글은 그림으로 알아보고 뺍니다. 새 낚시 그림이 생기면 그 해시를 `data/blocklist.json`의 `comic_images`에 더합니다.

## 주간 요약 탭

캘린더 옆 "주간 요약"은 사람이 쓰는 글입니다. 지금 글의 7일이 지났는데 새 글이 없으면 봇이 그 주(월요일 시작) 유행 순위로 **자동 초안**(작품별 대표 소식·일정·원문 요약, `"auto":true`)을 써 두고, 탭에 "자동으로 고른 초안" 안내가 붙습니다. 사람이 쓴 글은 7일 동안 봇이 건드리지 않습니다. 보드에 가장 많이 오른 작품(`data/meta.json`의 유행 순위) 중심으로 소식 몇 개를 골라 번호를 매기고, **설명은 보드의 기사 본문이 아니라 따로 검색한 공식 발표·언론 기사**로 정리해 그 글을 '출처'로 답니다. 내용은 `data/weekly.json` 하나이고 매주 덮어씁니다.

```json
{"week":"2026-10-26", "range":"10/26(일) ~ 11/1(일)", "title":"이번 주 요약 · 10월 마지막 주", "updated":"2026-10-24",
 "picks":[{"title":"소식 제목", "works":["작품명"], "category":"collab", "tag":"유행 1위",
           "when":"언제(자유 서식)", "where":"어디서", "desc":"검색해서 정리한 배경 설명(몇 문장)",
           "links":[{"label":"출처 이름", "url":"https://..."}], "items":["보드에 있는 관련 소식의 url"]}]}
```

`items`에 적은 주소가 보드 소식과 같으면 제목·날짜를 보드에서 가져와 보여 주고, 누르면 피드의 그 카드로 이동합니다(끝난 소식은 원문을 엽니다). `category`는 소식의 분류와 같은 값(`collab`·`live`·`exhibit` …), `tag`는 "유행 1위"·"마감 임박" 같은 짧은 배지입니다. 파일이 없거나 비어 있으면 탭에 "아직 없어요"만 나옵니다.

## 弾幕 탭 (미니 게임)

「まとめ結界 / MAID BUSTER LILLY」는 탭 하나짜리 세로 탄막 게임입니다. 시작·재도전은 화면을 두 번 탭(PC는 더블 클릭 또는 Z)하고, 화면을 드래그해 움직이고(PC는 방향키), 공격은 자동, 피탄 판정은 가운데 점 하나. 5스테이지(ミニオン襲来 → 蒼の艦隊 → オーバーロード再臨 → 要塞宙域 → 最終決戦)로 잡몹 → 중보스 → 보스(必殺技 3개) 순이고, 必殺技를 피탄·結界 없이 깨면 보너스. 그림은 운영자가 만든 스프라이트 시트(`assets/game/src/`)에서 `python3 assets/game/extract.py`로 잘라낸 `assets/game/*.png`이고, 우주 배경만 `python3 assets/game/paint.py`가 그립니다(둘 다 Pillow·numpy). 다른 조각을 쓰고 싶으면 `extract.py scan 폴더`로 번호 시트를 뽑아 `PICKS`의 번호를 바꾸면 됩니다. 게임 위 스킨 선택에서 「ホロ」를 고르면 홀로라이브 멤버 14명 중 하나로 플레이하고, 적·보스도 홀로 시트(`assets/game/src/sheet3.jpg`·`sheet4.jpg`)의 몬스터·보스로 바뀝니다(`python3 assets/game/extract.py holo`로 다시 자를 수 있음). BGM(칩튠, 스테이지·보스마다 다른 곡)은 브라우저가 소리를 내므로 ♪ BGM 버튼으로 끌 수 있습니다. 탄을 스치면(GRAZE) 점수가 오르고, 아주 가까이 피하면(CLOSE) 더 크게 오르며, 이어서 스칠수록 콤보 배율(최대 ×2)이 붙습니다. 오른 점수는 자기 옆에 숫자로 떠오릅니다. 난이도는 NORMAL / LUNATIC(탄량 ×1.3 · 탄속 ×1.2) 중 고르고, 스코어 보드도 난이도별로 따로입니다. 최고 점수(HI)는 각자 브라우저에만 남습니다.

**Holo Mobile 스코어 보드**와 같은 방식으로 弾幕 기록도 게시판 웹 앱의 `scores`(NORMAL)·`scores_lunatic`(LUNATIC) 시트에 쌓입니다.

## ラン (Test) 탭

「まとめラン」. 쿠키런처럼 옆에서 보며 끝없이 달리는 게임의 테스트판입니다(처음 만든 4레인 경주 「まとめダービー」는 폰으로 하기 불편해 2026-10에 이걸로 바꿨습니다). 선수 6명(スペ·スズカ·テイオー·ゴルシ·ライス·オグリ) 중 하나를 고르고, 탭하거나 위로 밀어 점프(공중에서 한 번 더), 아래로 밀어 슬라이드하며(슬라이드하던 손가락을 위로 밀면 바로 점프) ニンジン을 모으고 장애물을 피합니다. HP는 시간이 갈수록 줄고 부딪히면 확 줄어, 0이 되면 끝. 1200m마다 스테이지가 바뀌고(아침 잔디 → 저녁 더트 → 나이터 보스 → 비 → 눈 → 마법진 보스 …) 점점 빨라집니다. 스킬 게이지가 차면 선수별 스킬이 저절로 발동하고, 달리며 모은 파란 보석(코인)으로 보물 가챠(★1~5, 15종)를 돌려 3개까지 장착하면 다음 판부터 효과가 붙습니다. 선수 칸 아래에 그 선수의 유형과 스킬 설명이 한국어로 나옵니다(스킬이 걸려 있는 동안엔 게이지가 차지 않아요). 달리기 BGM은 운영자가 준 8비트 MIDI(`assets/race/src/bgm_run.mid`)이고, 바꾸려면 파일을 교체한 뒤 `python3 assets/race/midi2bgm.py --write`를 돌립니다. 보스 곡은 같은 MIDI의 사비 부분이고, 스타트 리프(두 번)와 사비 끝에서 운영자가 준 원곡에서 목소리만 뽑은 「うまぴょい うまぴょい」(`assets/race/umapyoi.mp3`)가 박자에 맞춰 나옵니다(📢 버튼으로 따로 끔). BGM은 ♪ 버튼으로 끌 수 있고, 끝나면 점수를 게시판 웹 앱의 스코어 보드(`scores_run` 시트)에 올릴 수 있습니다. 그림은 운영자가 만든 컨셉 시트(`assets/race/src/`)에서 잘라냅니다(선수 달리기·슬라이드 애니메이션은 `python3 assets/race/extract_anim.py`, 나머지는 `extract.py`).

## 放置 (Test) 탭 (숨김)

탭 버튼은 숨겨 두었고 주소 끝에 `#idle`을 붙이면 보입니다.

동인 서클을 키우는 방치형 게임의 테스트판입니다. 목표는 서클 랭크를 신입 서클에서 **기업 부스**까지 올리는 것(하루 몇 번 들르면 1~2주)이고, 코미케 참가(환생)로 열정을 모아 회차마다 더 멀리 갑니다. 설비(낙서 → 극장판)를 사 모으면 팬이 저절로 늘고, 화면 위 도트 장면에서 설비·일꾼·어시스턴트·손님이 지금 수치대로 움직입니다(누르면 응원, 연타하면 FEVER). 보드에 오늘·이번 주 행사가 있으면 이벤트 버프가 붙습니다. 기록은 각자 브라우저에만 남고, 테스트판이라 밸런스와 저장 형식이 바뀔 수 있습니다. 그림은 저장소 도트로 `python3 assets/game/idle.py`가 만듭니다.

## Holo Mobile 탭

## 참고

- 썸네일은 작품 공식 사이트의 대표 이미지(og:image)를 작게 줄여 `data/thumbs/`에 저장해 씁니다. 공식 사이트가 없으면 공식 PV 대표 이미지를 씁니다.
- 기사 본문은 저장하지 않고 제목·요약·원문 링크만 담습니다.
- 링크를 카카오톡·X 등에 붙이면 `assets/og.png`가 미리보기로 뜹니다. 바꾸려면 같은 크기(1200×630)의 PNG로 교체하면 됩니다. 공유 앱이 예전 이미지를 기억하고 있으면 주소 끝에 `?v=2` 처럼 아무 글자를 붙여 다시 공유하면 새로 읽습니다.
